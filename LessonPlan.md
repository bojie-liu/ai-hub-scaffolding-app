# University Lesson Plan
**Course**: The Modern Software Developer
**Topic**: AI-Augmented Software Engineering & Pedagogical Integration
**Duration**: 90 minutes
**Pedagogy**: TPACK Framework + Peer Assessment

---

## 1. Intended Learning Outcomes (ILOs)
By the end of the lesson, students will be able to:
1. **Analyze** the impact of AI tooling (e.g., GitHub Copilot, Tabnine) on software engineering workflows and pedagogical design *(TPACK-CK+TK)*.
2. **Apply** TPACK components to design lesson prototypes that integrate AI-assisted coding tools *(TPACK-PK)*.
3. **Evaluate** peer-designed lessons using structured rubrics focused on content relevance and technological fluency *(Peer Assessment)*.
4. **Collaborate** to address misconceptions about AI democratization risks (e.g., bias, over-reliance) *(Social Constructivism synergy)*.

---

## 2. Pre-Class Preparation (TPACK Foundation)
**Materials**:
- 10-min video: *"Democratizing Software: How AI is Reshaping Programming"* (linked to TPACK CK-TK integration)
- Article: *"TPACK Framework for Tech Integration in Education"* (key components: Content Knowledge, Pedagogical Knowledge, Technological Knowledge)
- **Pre-Test** (5 questions via LMS): Assess baseline understanding of AI coding tools and TPACK definitions (adaptive feedback maps misconceptions to peer assessment criteria).
- Guiding prompts for TPACK:
  - *Which AI tools address traditional software engineering challenges?*
  - *How can lesson objectives combine technical skills with critical thinking about AI ethics?*

---

## 3. Teaching & Learning Activities

### **Introduction (12 minutes)**
**Pedagogy-aligned hook**:
- Show 2-minute montage of AI coding tools (Copilot, Replit) juxtaposed with manual development.
- Poll: *"Does AI coding tooling reduce creativity in software development?"* (Mentimeter live word cloud for discussion trigger).

**Pre-Test Review**:
- Address common misconceptions from pre-test (e.g., "AI eliminates need for debugging" → link to peer rubric criteria).
- Real-World Connection: Share stats on AI tool adoption (Gartner: 70% of devs use AI assistants) and risks (data privacy issues).

---

### **Development Activities (63 minutes)**

#### **Activity 1: TPACK-Based Lesson Design Sprint (35 minutes)**
- **Task**: In pairs, design a 15-minute micro-lesson plan on AI-assisted debugging using TPACK lens:
  - **CK**: Core concepts (*AI tool limitations*).
  - **TK**: Tools selected (e.g., GitHub Copilot exercises).
  - **PK**: Pedagogical strategies (*collaborative code reviews*).
- **Deliverables**: A Miro board with lesson structure, including at least one interactive component (e.g., AI-generated code snippet for students to debug).

**Scaffolding**:
- Provide TPACK graphic organizer with labeled CK/TK/PK circles.
- Sample lesson template: "Plan → AI generate → Peer evaluate → Iterate (PAIR programming)"

---

#### **Activity 2: Structured Peer Assessment (20 minutes)**
- Exchange lesson plans using Peergrade.io.
- **Rubric Criteria** (TPACK + Peer Assessment alignment):
  1. Integration of AI tools with pedagogy (CK-TK synergy).
  2. Clarity of learning objectives (e.g., "Students will evaluate AI code suggestions using X standard").
  3. Ethical considerations (data bias, accessibility).
- **Process**:
  - Students calibrate by reviewing model responses (instructor provides exemplar).
  - Annotate lesson plans with constructive feedback (e.g., "Your CK-TK alignment is strong, but the PK lacks scaffolding for beginners").

---

#### **Activity 3: Collaborative Refinement (8 minutes)**
- Revise lesson plans based on peer feedback.
- Submit final version to LMS portfolio with reflection: *Which TPACK component did your peer critiques most improve, and why?*

---

### **Synthesis & Closure (15 minutes)**
- **Post-Test**: Same platform as pre-test, but with 3 conceptual application questions:
  - *"Evaluate how GitHub Copilot might affect code quality in legacy systems"* (targets ILO2).
- **Peer-Teaching**: In triads, summarize one peer's TPACK design that effectively addressed AI democratization.
- **Next Session Preview**: Connect to future topics on LLM prompt engineering for AI tool customization (pedagogical progression).

---

## 4. Assessment Methods

### **Formative Assessment**
- **TPACK Checkpoints**: Monitor TPACK component balance in Miro boards during Activity 1.
- **Peer Feedback Quality**: Analyze peer assessment rubrics for constructive specificity (e.g., "Vague: 'Needs improvement' → Specific: 'Expand CK on debugging theory'").
- **Poll**: *"Rate your confidence using TPACK to design AI-integrated lessons"* (Likert scale via Slido).

### **Summative Assessment**
- **Portfolio Rubric**:
  | Criteria | Exemplary (4) | Developing (2-3) | Needs Revision (1) | Pedagogy Link |
  |---|---|---|---|---|
  | TPACK Alignment | All 3 components synergistically integrated | 1-2 components evident | Missing key TPACK elements | TPACK Framework |
  | Ethical Consideration | Proactive AI risk mitigation strategy | Basic acknowledgment | Absent or superficial | Peer Assessment Rubric |
  | Feedback Incorporation | Extensive adoption of peer feedback | Partial implementation | Minimal/no changes | Peer Assessment |

## 6. Resources & Technology
- **TPACK Tools**: Miro (collaborative boards), GitHub Classroom (sample AI projects).
- **Peer Assessment Platforms**: Peergrade.io, LMS rubric builder.
- **AI Tools**: GitHub Copilot Sandbox (for live demos), Tabnine Code Completions.

---

## 7. Differentiation & Inclusivity
- **TPACK Scaffolds**:
  - Tiered templates for novice learners (pre-filled CK boxes).
  - Advanced options: Incorporate low-code/no-code platforms (Teachable Machine).
- **Accessibility**:
  - Captioned videos + transcripts for AI tooling demos.
  - Screen-reader-friendly Miro templates.
- **Inclusive Design**:
  - Case studies from global contexts (e.g., India's AI-assisted coding bootcamps).

---

## 8. Reflection & Improvement
- **TPACK Metrics**: Track lesson plan revisions prompted by peer feedback (quantify % of improvements).
- **Student Voice**: Collect feedback via Qualtrics survey:
  - *"Did TPACK rubrics clarify how to integrate AI tools pedagogically?"* (Likert scale + open response).
- **Modification Strategy**:
  - If peer assessments lack depth → Add more calibration examples with AI ethical dilemmas.
  - If TPACK designs show TK over PK → Schedule supplemental workshop on instructional design basics.

## Material Generation

### **Interactive Tools**
- `[Quiz: AI Tool Limitations - TPACK Alignment]` (3 questions):
  1. "Which component of TPACK focuses on sequencing learning activities when using GitHub Copilot?" *(Answer: Pedagogical Knowledge)*
  2. Drag-and-drop: Match tool features to TPACK domains (GitHub Copilot's code suggestions → Technological Knowledge).
  3. "What is a key risk of over-reliance on AI code generation?" *(Answer: Reduced critical thinking and debugging skills)*
- `[Flashcard: TPACK Components (TPACK)]`: Interactive definitions with software dev examples (e.g., CK = debugging theory).

### **Non-Interactive Activity**
*TPACK Case Study Development*:
> Provide a scenario where a learner struggles with AI-generated code violating accessibility standards. Instructors co-create a case study analyzing where TPACK components were misaligned (CK: accessibility principles, TK: Copilot limitations, PK: scaffolding strategies).

*Peer Assessment Feedback Guide*:
> Provide phrase starters for constructive peer reviews:
- "Your lesson effectively used [AI tool] to address [topic], however..."
- "Consider strengthening [TPACK domain] by adding..."

---

**Tone**: Scholarly yet practical, emphasizing TPACK's triadic structure and peer assessment's iterative improvement cycle.
**Implementation Note**: Use Miro and Peergrade for real-time collaboration; post class resources via LMS for accessibility.
