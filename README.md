# Lesson Plan template — content contract

This folder is a **pre-seeded template**. The design system and the application logic are already
written and correct. Your job is to fill in the lesson's content — not to build the site.

Read this file before writing anything.

---

## 1. Hard rules

**Never modify, rename, delete or duplicate these files:**

| File | Why |
|---|---|
| `styles.css` | The complete design system. Every class you may use is already here. |
| `app.js` | The complete engine bundle — nav, theme, progress, quiz, matching, polls, deck, timer, logs. |
| `custom.css` | Append-only escape hatch (see §7). Never rewrite it. |
| `README.md` | This contract. |

**Every page's chrome is also frozen** — do not restructure it:

- the `<head>` boilerplate (charset, viewport, stylesheet links, theme bootstrap script)
- `<a class="skip-link">`, `<main class="main" id="main">`, `<div class="wrap">`
- the `<nav class="page-nav" aria-label="Page navigation"></nav>` stub (filled by `app.js`)
- the `<script src="content.js"></script>` and `<script src="app.js"></script>` tags at the end
- the `<div class="deck-bar">` and `<div class="slide-progress">` blocks in `slides.html`

The site navigation, sidebar, pager, progress bar, footer and theme toggle are all **generated by
`app.js` from `content.js`**. No page contains them. Do not add them.

> There must be **no inline `<style>` blocks** anywhere. Need a new component? See §7.

## 2. What you must produce

   `<!-- ===== CONTENT:END ===== -->`, plus the `page-head` text (`eyebrow`, `h1`, `lede`, `tag-row`).
3. **Per-page `<title>` and `<meta name="description">`** (currently `FILL` placeholders).
4. **The interactive data** in `assessment.html` (questions, cards, polls, logs).

## 3. The content-marker convention

Each page has one editable region:

```html
<!-- ===== CONTENT:START =====
     guidance…
     ===== CONTENT:END ===== -->
```

Replace everything **inside** the region with the page's real content. Leave the `page-head` above it
and the `page-nav` stub below it exactly where they are.

`FILL` marks a value you must replace. `FILL or replace` means the surrounding default is a sensible
starting point you may keep or change.

Each section page ends with a **preparation checklist + "mark complete"** block — keep it, and:

- set each `data-track` to a unique id prefixed with the section (e.g. `section-3-block1`);
- set the `data-complete` attribute to the section's `id` from `content.js` (e.g. `section-3`);
- adjust the number of checklist items and update the `data-checklist-count` total.

## 4. Component library (structural classes)

Build all page content from these. They are all defined in `styles.css` and work in light and dark
mode.

**Layout** — `.wrap` · `.grid .grid--2 / .grid--3 / .grid--4` · `.card` (+`--flush`, `--accent`,
`--brand`, `--teal`, `--amber`, `--rose`, `--green`) · `.anchor-target` (add to any deep-linkable
block) · `.btn-row` · `.mt-1` `.mt-2` `.mb-0` `.center` `.muted` `.small` `.nowrap` `.sr-only`

**Headings & leads** — `.page-head` · `.eyebrow` · `.lede` (`h1`–`h4` need no class)

**Card internals** — `.card__head` · `.card__icon` (emoji or glyph, with `aria-hidden="true"`)

**Labels** — `.pill` + `--brand / --teal / --amber / --rose / --green / --ghost / --ai` · `.tag-row`

**Notes & emphasis** — `.callout` + `--info / --success / --warn / --danger`, with a
`<p class="callout__title">` first child · `.quote` · `.sentence-starter`

**Data** — `.table-scroll` > `table` with `<caption>` and `<thead>` · `dl.kv` (key/value)
· `.stats` > `.stat` > `.stat__num` + `.stat__lab` · `.sched` > `li` > `.sched__t`

**Sequences** — `.steps` (numbered, auto-counter) · `.acc` > `.acc__btn` + `.acc__panel` (collapsible)

**Tool / platform cards** — `.tool` > `.tool__head` (`.tool__logo`, `.tool__name`, `.tool__meta`) +
`.tool__body` · `.purpose` > `.purpose__row` > `.purpose__k`

**Activity blocks** — `.block` > `.block__head` (`.block__sub`) + `.block__body` · `.timeline-chip`

**Forms** — `.field` (on `input` / `textarea` / `select`) · `.field-row` · `.field-label`
· `.word-count` (or any element with `data-count`) · `.checklist` > `li` >
`label.check` > `input[type=checkbox][data-track]` + `.check__txt`

**Buttons** — `.btn` + `--primary / --teal / --ghost / --sm`

**Progress** — `.bar` (+`--sm`) > `.bar__fill` (driven by `app.js`; do not hand-set widths)

## 5. Interactive data contracts

`app.js` binds to these exact attributes. Keep them verbatim.

### Quiz — `assessment.html`

```html
<div class="quiz" data-quiz="unique-id" data-mode="single|immediate">
  <div class="quiz__head">…</div>
  <div class="quiz__body">
    <div class="q" data-correct="b" data-explain="HTML feedback shown after answering.">
      <p class="q__stem"><span class="q__num">1</span>Question?</p>
      <ul class="opts">
        <li><label class="opt"><input type="radio" name="pre1" value="a"><span class="opt__key">A</span><span>…</span></label></li>
      </ul>
      <div class="fb"></div>
    </div>
  </div>
  <div class="quiz__score">
    <button class="btn btn--primary btn--sm" type="button" data-quiz-check>Check all answers</button>
    <button class="btn btn--sm" type="button" data-quiz-reset>Clear</button>
    <span data-quiz-result class="small"></span>
  </div>
</div>
```

- `data-mode="single"` → a **Check all answers** button; nothing is revealed until it is pressed.
- `data-mode="immediate"` → feedback appears as soon as an option is chosen.
- `data-correct` is the `value` of the correct radio. `data-explain` may contain HTML.
- Every `<input>` in a quiz must share the same `name` **within a question** and a different one
  across questions.

### Matching / flashcards

```html
<div class="match" data-match="id">
  <div class="chips" data-pool>
    <button class="chip" type="button" draggable="true" data-id="card-1">…</button>
  </div>
  <div class="model-grid">
    <div class="model-card" data-model="m1">
      <h4>…</h4><p class="model-card__sub">…</p>
      <div class="drop" data-slot="concept" data-answer="card-1"><span class="drop__label">Label</span></div>
    </div>
  </div>
  <p class="small mt-1" data-match-result></p>
  <div class="btn-row"><button class="btn btn--sm" type="button" data-match-reset>Reset the set</button></div>
</div>
```

Each `.drop`'s `data-answer` must equal the `data-id` of the chip that belongs in it.

### Single-select poll

```html
<div class="poll" data-poll="id">
  <button class="poll-opt" type="button" data-id="o1">
    <span class="fill" data-fill="o1"></span>
    <span class="lblrow"><span>Option</span><span class="pct" data-pct="o1"></span></span>
  </button>
</div>
<div class="btn-row"><button class="btn btn--sm" type="button" data-poll-reset>Clear my vote</button></div>
```

### Two-axis poll

```html
<div class="axis" data-axis="me" role="img" aria-label="…">
  <span class="axis__lab axis__lab--t">Top</span>
  <span class="axis__lab axis__lab--b">Bottom</span>
  <span class="axis__lab axis__lab--l">Left</span>
  <span class="axis__lab axis__lab--r">Right</span>
</div>
<p class="small muted mt-1" data-axis-readout>…</p>
```

Counter element `[data-axis-count]` and clear button `[data-axis-clear]` are optional but should be
included alongside the `.axis-wrap` layout.

### Notes, decision log, exit ticket

```html
<!-- autosaved note -->
<textarea class="field" data-note="unique-key" rows="3"></textarea>
<p class="small muted word-count" data-count>0 words</p>

<!-- AI decision log (table + CSV export) -->
<div class="card" data-log="main"> … <tbody data-log-body></tbody> …
  <button class="btn btn--sm" type="button" data-log-add>+ Add row</button>
  <button class="btn btn--sm" type="button" data-log-export>Export CSV</button>
  <button class="btn btn--sm btn--ghost" type="button" data-log-clear>Clear log</button>
</div>

<!-- exit ticket -->
<div class="card" data-exit-ticket>
  <textarea class="field" data-exit="learned" rows="3"></textarea>
  <button class="btn btn--sm" type="button" data-exit-download>Download ticket</button>
  <button class="btn btn--sm btn--ghost" type="button" data-exit-clear>Clear</button>
</div>
```

Every `data-note`, `data-track` and `data-exit` value must be unique across the whole site.

### Slides — `slides.html`

One `<section class="slide" id="sN">` per slide, ids `s1…sN` in order, the **first** carrying
`is-active`. Put speaker notes in `<p class="slide-notes">` with a
`<span class="slide-note-label">Speaker notes</span>` inside. The `.deck-bar` controls, slide counter
and progress bar are already wired.

### Deck, timer & progress — already wired

These belong to the frozen chrome. Keep the attributes exactly as they are.

**Slide deck** (`slides.html`): `[data-deck]` on the `.slide-stage`, plus `[data-deck-count]`,
`[data-deck-fill]` and the controls `[data-deck-first]` / `[data-deck-prev]` / `[data-deck-next]` /
`[data-deck-full]`. Keyboard (arrows, `Home`/`End`, `F`), touch swipe and `#sN` deep-links are
handled by `app.js`.

**Countdown timer** (`slides.html`): `.timer` carrying `data-timer="<default minutes>"`, containing
`[data-timer-fab]`, `.timer__panel`, `[data-timer-display]`, `[data-timer-toggle]`,
`[data-timer-reset]` and `[data-preset="<minutes>"]` buttons. Move or duplicate this block onto any
page that needs live timing.

**Progress** (`index.html`): `[data-progress-overall]` wraps a `.bar` with a `.bar__fill`;
`[data-pct-label]` displays the percentage and `[data-progress-count]` displays `n / total`.
`[data-toc="sections"]` and `[data-toc="tools"]` are the two auto-built table-of-contents grids.
On section pages, `[data-checklist-count]` shows that page's ticked-item count. All of these are
written by `app.js` — never set their values by hand.

`.match`, `.quiz`, `.poll` and `.axis` are **wiring hooks**: `app.js` selects on them, so keep them
present even though only their children carry styling.

## 6. Copy & completeness

- All prose must be in the lesson's requested language.
- Write **complete** files: `<!DOCTYPE html>` on line 1, closing `</body></html>` at the end, no
  truncation, no `…` placeholders left behind.
- Cover the input lesson plan fully — do not drop required content.
- Every heading you link to from the sidebar or a jump-link should have an `id` and the
  `anchor-target` class.
- Use real, working external links with `target="_blank" rel="noopener"`.

## 7. Escape hatch

`styles.css` covers the component library. If — and only if — a lesson genuinely needs a component
that cannot be built from it, **append** a new rule to `custom.css`:

```css
/* custom.css */
.my-thing { border-left: 5px solid var(--brand-2); }
```

Rules for `custom.css`: append only, never rewrite it, prefix class names, and reuse the design
tokens (`var(--brand-2)`, `var(--border)`, `var(--radius)`, …) so both themes keep working. Leaving it
empty is normal and preferred.

## 8. Verifying your work

- Every page must load with `title`, `styles.css` link, `content.js` and `app.js` script tags.
- Open `index.html`: the sidebar, TOC cards and progress bar should render from `content.js`.
- Open `assessment.html`: choosing a quiz answer must reveal feedback; a chip must be placeable in
  its matching `.drop`; the poll must tally; the decision log must accept a row and export CSV.
- Toggle the theme (☽ / ☀ in the top bar) — every component must stay legible.
- No console errors.
